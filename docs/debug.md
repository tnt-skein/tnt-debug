# Отладка

`tnt-debug` — средства разработчика: показать любое значение человеку,
записать его в журнал с местом вызова, замерить кусок кода и увидеть,
где стоят файберы узла.

```lua
local dbg = require('tnt.debug')

dbg.describe({ id = 7, password = 'hunter2', tags = { 'a' } })
--> {
-->     id = 7,
-->     password = [скрыто],
-->     tags = {
-->         "a"
-->     }
--> }

local rows = dbg.dump(box.space.customers:select(nil, { limit = 3 }))
--> в журнале: … I> отладка place=app/customers.lua:41 value="{ tuple { 1, \"Иван\" }, … }"

dbg.measure(function() json.encode(doc) end, { times = 1000 })
--> { times = 1000, total = 0.0041, mean = 4.1e-06, min = 3.8e-06, max = 2.1e-05, yields = 0, allocated = 81920 }

dbg.fibers({ name = 'worker' })
--> { { id = 112, name = 'worker', switches = 40, memory = { used = 0, total = 520664 },
-->     stack = { 'sleep in [C]:-1', '(unnamed) in app/worker.lua:14' } } }
```

Переменную зовут `dbg`, а не `debug`: `debug` — встроенная библиотека
Lua, и местная переменная с этим именем закрыла бы в файле
`debug.traceback` и `debug.getinfo`.

Зависимости: [`tnt-log`](https://github.com/tnt-skein/tnt-log) (правило
тайн, отметки, журнал `dump`), [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(проверки настроек), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock)
(монотонные часы замера) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена часов, счётчиков, сборщика мусора и сведений о файберах
в проверках). Настроек у пакета нет: ни `configure`, ни `new`.

## Зачем пакет

1. **Встроенные способы показать значение не годятся.** Проверено
   на Tarantool 3.8: `yaml.encode` бросает на функции и на указателе
   (`unsupported Lua type 'function'`), печатает пароль как есть,
   не сортирует ключи (`100` раньше `1`) и выводит таблицу из ста тысяч
   чисел целиком — 788 КБ; `json.encode` бросает на кольце
   (`Too high nest level`) и пишет uuid и decimal строками, неотличимыми
   от настоящих строк; `tostring` таблицы — адрес в памяти. `describe`
   не бросает никогда, прячет тайны, держит пределы и называет род
   значения.
2. **Место вызова и журнал.** `print` уходит в stdout, который у узла под
   `tt` никто не читает, и не говорит, откуда он. `dump` пишет в журнал —
   канал, который у узла есть всегда, — с файлом и строкой вызова и отдаёт
   значения обратно, так что встаёт в середину выражения.
3. **Время на узле Tarantool обманывает без двух чисел.** Вызов, который
   уступил файбер, отдал узел соседям, и его время включает чужую работу;
   внутри транзакции memtx уступка её обрывает. Память, выделенная
   вызовом, оплачивается сборщиком мусора позже и не тем, кто выделял.
   `measure` к времени прикладывает число уступок и выделенные байты.
4. **Где стоит файбер.** Узел, который «висит», почти всегда держит
   файбер, ждущий того, что не наступит. `fiber.info()` показывает стек
   вперемешку с кадрами C, нумерацией и приставками источника, таблицей
   по номерам без порядка; `fibers` отдаёт список по номерам и только
   кадры Lua.

## Как пользоваться

### Что умеет фасад

| Функция | Что делает |
|---|---|
| `describe(value, options)` | показ значения строкой: многострочный либо в одну строку |
| `dump(...)` | запись значений в журнал `tnt.debug` с местом вызова; отдаёт аргументы |
| `measure(fn, options)` | замер функции: время, уступки файбера, выделенная память |
| `fibers(options)` | снимок файберов узла списком по номерам, со стеком |
| `JOURNAL` | имя журнала `dump`: `'tnt.debug'` |

### Показ значения: `describe`

```lua
dbg.describe({ 1, 'два', id = 7, [1.5] = true, ['x-y'] = box.NULL })
--> {
-->     1,
-->     "два",
-->     [1.5] = true,
-->     id = 7,
-->     ["x-y"] = box.NULL
--> }

dbg.describe({ a = { 1, 2 } }, { inline = true })  --> '{ a = { 1, 2 } }'
```

Запись похожа на таблицу Lua, и порядок в ней постоянный: сначала
последовательность `1..n` без ключей, затем числа по возрастанию, строки
по алфавиту байтов, а прочие ключи — `false` и `true`, таблицы,
функции — по их показу: `[false]`, `[true]`, `[{ 1 }]`. Порядок
`pairs` не задан, и один объект, показанный дважды, иначе выглядел бы
по-разному. Ключ-имя пишется без скобок, прочие — в скобках: `["end"]`,
`["x-y"]`, `[10]`, `[{ 1 }]`. Обход идёт мимо метаметодов (`next`,
`rawget`): показ смотрит, что лежит в таблице, а `__index` чужого объекта
мог бы и бросить.

Род значения виден по записи:

| Значение | Показ |
|---|---|
| строка | `"узел"`: в кавычках, `\n`, `\t`, `\"`, прочие управляющие — `\x01` |
| строка не в UTF-8 | каждый байт старше 127 — `\xD0\xB6\xFF` |
| число | `7`, `-0`, `0.1`, `0.30000000000000004`, `nan`, `inf`: читается обратно тем же числом |
| 64-битное целое | `1LL`, `18446744073709551615ULL` |
| `box.NULL` | `box.NULL` |
| uuid, decimal, datetime, интервал | `uuid("…")`, `decimal("1.50")`, `datetime("2026-09-25T00:00:00 Europe/Moscow")`, `interval("+1 days")` |
| ошибка box | `box.error("нет связи")` |
| кортеж | `tuple { 1, "a" }` |
| функция | `function /srv/app/http.lua:12`, у функции ядра — `function [C]`, у встроенной в LuaJIT — `function [builtin:len]` |
| прочее | своя печать: `fiber: 104`, `thread: 0x…`; бросившая печать — `[userdata]` |

Отметки — те же слова, что в журнале: `[скрыто]` у тайны, `[кольцо]`
у таблицы, внутри которой мы сейчас находимся, `[глубже]` у таблицы глубже
предела. Вторая ссылка на ту же таблицу из соседнего поля кольцом
не считается и показывается снова: это законное устройство данных.

```lua
local node = { name = 'узел' }
node.self = node
dbg.describe(node, { inline = true })  --> '{ name = "узел", self = [кольцо] }'
```

**Тайны.** Значение под именем-тайной (`password`, `token`, `api_key`, …
— список `secret_hints` журнала) — `[скрыто]`, какого бы рода оно
ни было. Строки проходят правилом журнала `scrub`: пароль в адресе
и значение подозрительного параметра внутри текста.

```lua
dbg.describe({ url = 'http://user:secret@host/x', token = { id = 1 } }, { inline = true })
--> '{ token = [скрыто], url = "http://user:[скрыто]@host/x" }'
```

**Пределы** — таблицей настроек:

| Настройка | Что задаёт | По умолчанию |
|---|---|---|
| `depth` | сколько уровней таблиц раскрывается; пустая таблица и глубже — `{}` | 8 |
| `items` | сколько пар показывается **на всё описание**, не на таблицу | 100 |
| `length` | сколько байт строки показывается, от 1 до 4096; режется по границе знака | 200 |
| `inline` | одной строкой | `false` |

Число пар — на всё описание, потому что предел на таблицу при восьми
уровнях пропустил бы миллиарды пар. Не вошедшее таблица называет числом,
обрезанная строка — числом байт:

```lua
dbg.describe({ 1, 2, 3, 4, 5 }, { items = 3, inline = true })  --> '{ 1, 2, 3, … ещё 2 }'
dbg.describe(('x'):rep(300), { length = 10 })                 --> '"xxxxxxxxxx"… (300 байт)'
dbg.describe({ a = { b = { c = 1 } } }, { depth = 2, inline = true })
--> '{ a = { b = [глубже] } }'
```

Негодная настройка — ошибка программиста, бросок на строке вызывающего:

```
настройки показа: ключа «depht» нет, есть depth, inline, items, length
настройки показа.depth — число больше 0, а не 0
настройки показа.length — число от 1 до 4096, а не 5000
```

### Запись в журнал: `dump`

```lua
local customer = dbg.dump(find(id))        -- customer тот же, что вернул find
dbg.dump(a, nil, b)                        -- три значения одной записью
dbg.dump()                                 -- только место: «дошли сюда»
```

Запись идёт в журнал `tnt.debug` на уровне info, значения — одной строкой
в поле `value` через запятую, место вызова — полем `place`:

```
2026-09-26 12:00:00.000 [4012] main/104/app.lua/tnt.debug debug.lua:86 I> отладка place=/srv/app/customers.lua:41 value="1, nil, \"x\""
```

Место — полем, а не заголовком записи: заголовок ядро берёт из кадра
внутри пакета — `debug.lua:86` в записи выше. Уровень info, а не debug:
отладочный уровень у ядра по умолчанию выключен, и `dump`, который
молчит, пока не переставишь уровень, только сбивал бы с толку. Заглушить
записи — уровнем модуля в разделе `log` конфигурации:

```yaml
log:
  modules:
    tnt.debug: warn
```

`dump` отдаёт ровно то, что получил, со всеми `nil`. Хвостовой вызов
`return dbg.dump(x)` снимает кадр вызывающего со стека (так делает
LuaJIT), и место уходит к тому, кто позвал функцию; место на своей
строке даёт `return (dbg.dump(x))` — скобки снимают хвост, но оставляют
одно значение. У `dump`, с которого начат поток (`coroutine.wrap(dbg.dump)`),
вызывающего нет, и поля `place` в записи нет.

### Замер: `measure`

```lua
dbg.measure(function() box.space.customers:get(7) end, { times = 1000 })
--> { times = 1000, total = …, mean = …, min = …, max = …, yields = 0, allocated = … }
```

| Поле | Что значит |
|---|---|
| `times` | сколько раз позвана функция (`times` настройки, по умолчанию 1) |
| `total`, `mean`, `min`, `max` | секунды: на все вызовы, в среднем, самый быстрый, самый медленный |
| `yields` | сколько раз файбер уступил за все вызовы (`fiber.self():csw()`) |
| `allocated` | сколько байт выделено за все вызовы (`gc_allocated` из `misc.getmetrics()`) |

Время — монотонными часами `tnt-clock`, а не отметкой цикла событий:
работа без уступки по отметке цикла занимает ноль. `allocated` —
выделенное, а не занятое: освобождённое сборкой из него не вычитается.
Сам счёт памяти стоит таблицы ядра на вызов; её цена меряется парой
вызовов подряд перед замером и вычитается, так что пустая функция даёт
ноль. Пара идёт при остановленном сборщике мусора и вне трасс JIT:
шаг сборщика выделяет и сам — зовёт финализаторы, ужимает буферы, —
и, придись он на пару, цена вышла бы завышенной, а `allocated` —
отрицательным; выход из трассы, пока сборщик вызывает финализаторы,
делает такой шаг и при остановленном сборщике. Сборщик пускается
снова, только если шёл до замера: остановленный вызывающим остаётся
стоять. Сами вызовы функции идут при работающем сборщике, поэтому
`allocated` бывает больше того, что выделила функция, но не меньше
(«Чем пришлось поступиться» ниже). Функция зовётся без аргументов,
её бросок уходит вызывающему как есть. Негодные аргументы — бросок:

```
замеряемая функция — функция или вызываемая таблица, а не строка
настройки замера.times — число больше 0, а не 0
```

### Снимок файберов: `fibers`

```lua
dbg.fibers()                          -- все файберы, со стеком
dbg.fibers({ name = 'worker' })       -- только те, в имени которых есть «worker»
dbg.fibers({ stack = false })         -- без стека: дешевле
```

Список по возрастанию номера, у файбера — `id`, `name`, `switches`
(сколько раз переключался), `memory` (`used` и `total` — байты области
памяти файбера, где ядро держит временные выделения запроса) и `stack` —
кадры Lua сверху вниз строками `sleep in [C]:-1`,
`(unnamed) in app/worker.lua:14`. Кадры C выброшены: место в коде
приложения по ним не найти. Имя сравнивается подстрокой, а не образцом:
`'.b'` находит `a.b`, но не `ab`.

## Чем пришлось поступиться

- **`dump` не останавливает работу.** Показать и прервать нечего: узел
  обслуживает сотни запросов, и остановка процесса сорвала бы все.
  Прервать свой запрос умеет `error()`, а показать — `dump` перед ним.
- **Длинный показ режет журнал.** Строка поля записи журнала держится
  до 4 КБ, и `value` длиннее обрезается журналом с многоточием: сотня
  пар по двести байт в неё не входит. Голова записи при этом остаётся,
  а таблицу целиком показывает `describe` в консоли узла.
- **Забытый `dump` пишет и в бою.** Тайны из записи вырезаны, но личные
  данные — имя, адрес — нет: правило тайн знает имена полей с ключами
  и паролями, а не с людьми. `dump` в коде, уходящем в бой, не оставляют;
  страхует уровень `tnt.debug: warn` в конфигурации боевого кластера.
- **Порядок большой таблицы.** Для сортировки берутся первые 10 000
  ключей по обходу (`SCAN`), остальные только считаются: сортировка
  миллиона ключей — секунда работы без уступки. У таблицы больше
  10 000 ключей показаны не самые первые по порядку, а первые из взятых.
- **Ключ-таблица глубже предела** показывается `[[глубже]]`: ключ идёт
  тем же показом, что значение, и предел у них общий.
- **Счёт памяти видит сборщик.** Сборщик на время вызовов функции
  не останавливается: в работе он не стоит, а замер тысячи вызовов копил
  бы без него весь их мусор. Шаг сборщика, пришедшийся на вызовы,
  прибавляет к `allocated` свои выделения — финализаторы чужого мусора,
  ужатые буферы: после мусора с финализаторами пустая функция в части
  замеров получает 1280 байт. Ниже нуля счёт не уходит. Точный счёт
  того, что выделяет сам код, — при остановленном сборщике:
  `collectgarbage('collect')` и `collectgarbage('stop')` до замера,
  `collectgarbage('restart')` после.
- **Счёт памяти видит JIT.** Трассы LuaJIT живут в куче сборщика: первая
  тысяча вызовов, на которой цикл замера становится горячим, выделяет
  лишний килобайт-другой. И наоборот, выделение, которое JIT утопил
  (таблица, не покинувшая трассу), не выделяется вовсе и не считается.
  Замер показывает, что случилось на самом деле; точный счёт того, что
  просит сам код, — при `jit.off()` и `jit.flush()`: `jit.off()` не даёт
  заводить трассы, но собранные раньше исполняются дальше. Хук покрытия
  выделяет память на каждой строке, поэтому под `luatest --coverage`
  счёт больше.
- **Время включает чтение часов** — десятки наносекунд на вызов. Функцию
  короче микросекунды меряют с `times` в тысячи и смотрят на `mean`.
- **Стек есть не везде.** Ядро собирает стек файбера только там, где
  собрано с его поддержкой; где её нет, `stack` пуст, а не отсутствует.

## Проверки

Проверки лежат в `test/` и идут на luatest: `make test`. Показ каждого
рода значения и таблиц сверяется точными строками, пределы — на границах,
отказы настроек — текстом и местом вызывающего. Запись `dump` видна
ловушкой журнала, которая встаёт на место журнала ядра через
`_set_source` пакета `tnt-log`. Замер идёт с двойниками часов,
счётчиков и сборщика и живьём — на настоящих счётчиках, снимок —
с двойником `fiber.info` и живьём — на настоящем файбере. Точный живой
счёт памяти идёт с остановленным сборщиком, выключенными JIT и хуком
покрытия: каждый из них выделяет память сам («Счёт памяти видит
сборщик» и «Счёт памяти видит JIT» выше). Калибровку сверяют три
проверки: двойник сборщика видит порядок остановки и пуска, заголовки
байткода — что калибровка и счёт по умолчанию не входят в трассы JIT,
а двести замеров пустой функции после мусора с финализаторами —
при работающем сборщике и включённом JIT — не дают ни одного
отрицательного `allocated`.

Проверок — 85; покрытие строк — 100 %, убитых мутантов — 100 %
(288 мутантов в пяти модулях).
